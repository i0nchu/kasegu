# 交給 Codex 的獨立驗證：EPR15

凍結版本：git tag `alpha-epr15-v1`（分支 `research/claude-alpha`）。請**不要**修改參數；驗證的是現象，不是再找更好的參數。

## 1. 要驗證的主張

1. 下跌趨勢中（收盤 < EMA240），掛在 12 個波動單位以下的買單成交後，價格在幾分鐘內回彈，扣成本後為正。
2. 回彈主要發生在成交後前 5 分鐘；扣掉市場同期報酬後，之後的漂移接近 0（不是風險補償）。
3. 上漲趨勢的同樣買單、任何方向的賣單都沒有這個現象。
4. 可交易規則 EPR15 在 40 幣 24 個月平均淨 +0.24% / 筆，排除崩盤日仍 +0.24%，隨機進場對照 −0.10%。

## 2. 凍結的規則

| 項目 | 值 |
|---|---|
| 方向 | 只做多 |
| 趨勢 | 下單那根 1m 收盤價 < EMA(240)（adjust=False） |
| 波動單位 vol% | (mean(TR,60)/收盤 ×100 + mean((H−L)/C ×100, 60)) / 2 |
| 掛單價 | (收盤 + tick/2) × (1 − 12 × vol%/100)，向下取整到 tick，Post-Only |
| 掛單生命 | 一分鐘，每根收盤撤單重掛 |
| 成交判定 | 下一根最低價 + tick/2 < 掛單價 |
| 出場 | 成交那根起算第 15 根收盤市價賣出（taker 0.05% + 滑價 0.02%），或 3% 停損 |
| 倉位 | 每幣同時一倉；名義 297 USDT |
| 成本 | Maker 0.02% 進、Taker 0.05% 出、滑價 0.02%、資金費率照實 |
| 預熱 | EMA 需 720 根以上 |

程式：`research/sim.py`（`Cfg(k=12, trend="against", sides="long", sl=3.0, exit="time", max_hold=15)`）、`research/alpha/a3_candidate.py`。

## 3. 資料

- 1m klines、fundingRate：data.binance.vision monthly（`research/download.py`），2024-10 ~ 2026-09。
- tick size：`data/research/ticks.json`（exchangeInfo）。
- 40 幣清單：`research/alpha/data.py` 的 `UNIVERSE`。
- 逐筆成交（成交真實性）：daily aggTrades，抽樣清單 `data/research/alpha/trade_days_A2.csv`。

## 5. 建議的獨立檢查（請用自己的程式，不要直接呼叫上面的模組）

1. 從規格重寫成交與出場，重現第 4 節數字。
2. 新資料：2026-10 之後（日 K 線或之後的月檔）與 40 幣以外的幣，規則不變。
3. 出場滑價實測：用 aggTrades 取出場時刻之後的真實成交價（賣方吃買價），量出 stress 日的實際滑價；若中位數 > 0.2%，現象不可交易。
4. 急殺當下的交易所行為：用引擎模擬盤或歷史回放確認 Post-Only 單在急殺時不被拒、撤單重掛延遲 < 數秒。
5. 若可行，用 1 秒或逐筆資料重建「成交時刻 → 1/5 分鐘後」的 markout，確認回彈不是 1m 收盤價的假象。

## 6. 已知風險

- 出場滑價 > 0.2% 時淨值歸零（A3 slip0.2）。
- 崩盤日（49 天）報酬極不穩定；3% 停損 257 / 1,918 筆觸發。
- 每幣每月約 2 筆，資金容量受限於低頻，單筆容量則足夠（掛單價以下一分鐘成交額中位數約 60 萬 USDT）。
- 低波動大幣（BTC、ETH、BNB、TRX、BCH）在 Y2 幾乎不賺；本規則未排除它們，避免事後選幣。
